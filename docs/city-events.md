## 구현

- `lib/city-events.js`: HTML 구조와 일정 항목으로 추출한다. 제목, 행사기간, 시간, 장소, 주최기관, 사실 항목으로 구성한 내용, 원문 URL을 저장한다. 원문 전체 문장이나 첨부파일은 복제하지 않는다.
- `news-admin.html`: 기존 뉴스 승인 관리자 화면 안에 행사 승인 대기 목록과 “정읍시청 행사 지금 수집하기” 버튼 추가. 기존 로그인 쿠키·출처 검사 재사용.
- `functions/api/news-admin.js`: 인증 후 city-list / city-collect / city-approve / city-reject 작업 추가. 기존 뉴스 기능과 AI 사용 방식은 그대로 유지하되 행사 경로는 AI에 접근하지 않는다.
- `functions/api/city-collect.js`: 예약 실행 전용 POST. 관리자 쿠키가 아닌 32자 이상 서버 비밀값으로 인증한다. 비밀값은 코드에 넣지 않는다.
- `collectors/scheduler.js`: 별도 예약 Worker. 한국시간 07:00,17:00 = UTC 22:00,08:00. Cloudflare Pages 자체에는 cron을 설정하지 않는다.
- 행사 원문 boardId+dataSid를 기본 식별자로 사용. 같은 제목+행사 시작일+장소로 다른 게시판과 기존 수동 게시글도 비교한다.
- 지난 행사는 신규 대기에서 제외. 날짜 불명은 자동 추정하지 않고 검토 대상으로 남기며 승인 차단. 변경·취소된 게시행사는 기존 글 ID로 승인 후 반영하므로 조회수·좋아요·댓글 유지.
- 삭제/접속오류는 취소로 판단하지 않는다. 원문 확인 실패를 표시하고 승인 차단한다.
- 실행 중복 잠금, 수집 오류·실행 결과 기록, 검토 이후 원문 변경 시 이전 승인 차단.
- 새 테이블은 city_events / city_collection_runs / city_collection_lock뿐이다. 기존 테이블 삭제·초기화·전체 덮어쓰기 없음.

## 포스터 허가

기본은 포스터 미수집이다. 원문 상세 내용 안의 이미지에 대해 운영자가 이용허가를 검토한 경우에만 Pages 환경변수 `CITY_POSTER_PERMISSIONS`에 이미지별 허가를 등록한다. 원문 상단/하단의 공통 공공누리 로고만으로 이미지 허가를 인정하지 않는다. 상업적 이용·변경 허용, 증빙 URL, 출처 표기가 모두 있어야 한다. 이미지 주소는 정읍시청 동일 출처만 허용한다. 허가된 이미지는 시청 원본 URL을 사용하며 원본 파일을 다른 저장소로 내려받지 않는다.

```json
{
  "https://www.jeongeup.go.kr/upload_data/실제_허가된_이미지.jpg": {
    "commercial": true,
    "derivatives": true,
    "evidenceUrl": "https://www.jeongeup.go.kr/실제_이용허가_증빙",
    "attribution": "작성연도·저작권자·원문 주소 등 실제 출처"
  }
}
```

허가가 없으면 자체 제작 `event-placeholder.svg`를 사용하고 원문 링크를 표시한다.

## 운영 연결 순서

1. 운영 D1 `ds`에 대해 Cloudflare D1 Time Travel 복구 가능 시점 확인 또는 내보내기를 먼저 확보한다. 데이터가 있는 운영 D1을 새 DB로 교체하지 않는다.
2. 변경 소스를 기존 Pages 프로젝트에 배포한다. 기존 `ds`, `NEWS_ADMIN_PASSWORD`, R2 및 나머지 바인딩과 변수 보존. 기존 관리자 로그인 정상 여부 확인.
3. 관리자 → 뉴스 승인 → 시청 행사 지금 수집하기. 실제 수집 결과, 새 후보, 중복, 지난 행사, 원문 오류 확인. 후보 1건 승인하여 행사 목록 표시 확인.
4. 서버 비밀값을 안전하게 생성하여 Pages와 예약 Worker 양쪽에 같은 `CITY_COLLECTOR_SECRET`을 설정한다. 비밀값을 저장소·이슈·브라우저 주소·로그에 기록하지 않는다.
5. `collectors/`에서 Cloudflare 공식 Wrangler 도구로 `wrangler secret put CITY_COLLECTOR_SECRET`, `wrangler deploy` 실행. 기존 다른 Worker/Pages 설정을 바꾸지 않는다. cron은 `wrangler.toml`에 있다.
6. 예약 Worker 로그와 관리자 최근 실행 결과로 실제 예약 작동을 확인한다. 이 단계가 완료되기 전에는 자동수집 활성화 완료라고 보고하지 않는다.

## 검증 및 현재 한계

`node --test tests/city-events.test.mjs` (Node 24 이상, 내장 SQLite 사용). 9개 테스트: 일정·한국시간, URL 중복, 이미지 허가, 승인·변경·취소 시 조회수/댓글 보존, 기존 글 중복·지난 행사, 원문 오류, 실행 잠금·robots, 예약 API 인증, 기존 게시글 삭제 시 승인 대기 유지.

수집 범위는 일정 게시판 이번 달/다음 달 각 2페이지, 공지 최근 3페이지, 문화관광 최근 2페이지이다. 원문 재확인과 신규 상세 수집은 실행당 총 30건이며 오래 확인하지 않은 항목부터 순환한다. 초과는 다음 실행 대상으로 수집 결과에 표시한다. 더 먼 미래와 오래된 목록에만 있는 신규 행사는 범위 확대가 필요하다. 이미지에만 적힌 정보, HWP/PDF 첨부 안의 일정, 자연어로 복잡하게 표현한 일정은 AI/OCR 없이 확정하지 않는다. 정보가 부족하면 검토 대상으로 표시한다. 관련 취소 공지가 새 게시글로만 올라오고 기존 원문은 그대로인 경우 자동으로 서로 연결하지 못할 수 있어 관리자 원문 확인이 필요하다.

운영 데이터에 대한 실제 승인/변경·예약 실행 검증은 배포 후 수행해야 한다. 이 문서는 실행 기록을 대신하지 않는다.
